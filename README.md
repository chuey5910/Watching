# จับตา. — กระดานข่าวเฝ้าระวังสถานการณ์

เว็บกระดานข่าวภายในองค์กร (self-hosted) ที่รวบรวมข่าว **การเมือง · การปกครอง · ความเดือดร้อนของประชาชน · ภัยพิบัติ · การชุมนุม/ประท้วง/คัดค้าน** จากสื่อหลัก สื่อท้องถิ่น สื่อต่างประเทศ หน่วยงานรัฐ และบัญชีโซเชียลของบุคคลที่เฝ้าติดตาม แล้วจัดกลุ่มข่าวเรื่องเดียวกัน จัดระดับ (จำเป็น / สำคัญ / สมควรรู้ / น่าสนใจ) และให้ผู้ใช้ **ปักหมุดข่าวที่ต้องการให้แสดงบนสุด** ได้ทั้งด้วยมือและด้วยกฎอัตโนมัติ

เข้าถึงได้เฉพาะภายใน **Tailscale Tailnet** · ผู้ใช้ใหม่ต้อง **สมัครแล้วรอผู้ดูแลอนุมัติ** · ทุกการเข้าใช้และการกระทำถูกบันทึกลง **log**

---

## 1. ติดตั้ง (Mac mini / Linux)

ต้องมี Python 3.11+ และ Tailscale ติดตั้งอยู่แล้วบนเครื่อง

```bash
git clone <หรือแตก zip> jabta && cd jabta
./scripts/install.sh          # สร้าง .venv, ติดตั้งไลบรารี, สร้าง .env, สร้างฐานข้อมูล + สื่อเริ่มต้น 148 แหล่ง
./scripts/run.sh              # รันที่ http://127.0.0.1:8085 (gunicorn)
```

เปิดเบราว์เซอร์ **บนเครื่องนั้น** ที่ `http://127.0.0.1:8085` → สมัคร **บัญชีแรกจะเป็นผู้ดูแลระบบ (admin) และใช้งานได้ทันที** บัญชีถัดไปทั้งหมดจะอยู่ในสถานะ "รออนุมัติ" จนกว่า admin จะอนุมัติในหน้า **ผู้ใช้**

จากนั้นกด **"ดึงข่าวตอนนี้"** บนกระดานเพื่อเริ่มเก็บข่าวครั้งแรก (1–3 นาที) หลังจากนั้นระบบดึงเองทุก 10 นาที

> รันแบบไม่ใช้สคริปต์: `python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt && cp .env.example .env && FLASK_APP=app.py flask seed && python app.py`

## 2. เปิดให้เครื่องอื่นใน Tailnet เข้าใช้ (Tailscale)

แอปผูกกับ `127.0.0.1` เท่านั้น แล้วให้ `tailscale serve` เป็นตัวเปิดออก Tailnet พร้อม HTTPS อัตโนมัติ

```bash
./scripts/tailscale-serve.sh
# → https://<ชื่อเครื่อง>.<tailnet>.ts.net
```

สิ่งที่ระบบทำร่วมกับ Tailscale:

| กลไก | รายละเอียด | ตั้งค่า |
|---|---|---|
| **IP gate** | ปฏิเสธ (403) ทุกคำขอที่ไม่ได้มาจาก `100.64.0.0/10`, `fd7a:115c:a1e0::/48` หรือ loopback — แม้แอปจะถูกเปิดพอร์ตออกโดยไม่ตั้งใจก็เข้าไม่ได้ | `TAILSCALE_ONLY=1` (ค่าเริ่มต้น) · เพิ่ม LAN ได้ที่ `EXTRA_TRUSTED_CIDRS` |
| **ตัวตน Tailscale** | `tailscale serve` ส่ง header `Tailscale-User-Login` มาด้วย ระบบเชื่อ header นี้ **เฉพาะเมื่อคำขอมาจาก loopback** (คือมาจาก tailscale serve จริง) เมื่อผู้ใช้ที่อนุมัติแล้วล็อกอินด้วยรหัสผ่านครั้งแรกผ่าน serve ระบบจะผูกตัวตนไว้ ครั้งถัดไปเข้าอัตโนมัติ | `TRUST_TAILSCALE_HEADERS=1` · admin ยกเลิกการผูกได้ในหน้า ผู้ใช้ |
| **IP จริงใน log** | อ่านจาก `X-Forwarded-For` เฉพาะเมื่อ proxy มาจาก loopback | อัตโนมัติ |
| **Cookie ปลอดภัย** | เมื่อเข้าผ่าน https ให้เปิด | `SESSION_COOKIE_SECURE=1` |

ถ้าอยากจำกัดให้เฉพาะบางคนใน Tailnet เข้าถึงพอร์ตนี้ได้ ให้กำหนดเพิ่มใน Tailscale **ACL** (เช่น อนุญาตเฉพาะ tag/กลุ่มที่ต้องการไปยัง `<เครื่อง>:443`) — ระบบยังต้องผ่านการสมัคร+อนุมัติอีกชั้นอยู่ดี

**รันถาวร:** Linux ใช้ `scripts/jabta.service` (systemd) · macOS ใช้ `scripts/com.jabta.board.plist` (launchd) · หรือ Docker: `TS_AUTHKEY=tskey-... docker compose up -d` (มี Tailscale sidecar ให้ในตัว)

## 3. ระบบผู้ใช้: สมัคร → รออนุมัติ → ใช้งาน

- **สมัคร** ที่ `/register` กรอกชื่อผู้ใช้ ชื่อที่แสดง เหตุผล/หน่วยงาน และรหัสผ่าน (≥ 8 ตัว)
- บัญชีใหม่มีสถานะ `pending` — ล็อกอินได้แต่จะถูกส่งไปหน้า "รออนุมัติ" เข้ากระดานไม่ได้
- **admin** เห็นคำขอในหน้า **ผู้ใช้** พร้อมเหตุผลและตัวตน Tailscale (ถ้ามี) → อนุมัติ / ปฏิเสธ / ระงับ / ตั้งเป็น admin / รีเซ็ตรหัสผ่าน / ปลดล็อก
- ใส่รหัสผิดเกิน `MAX_LOGIN_FAILS` (8) ครั้ง → ล็อก `LOCKOUT_MINUTES` (15) นาที
- ปิดรับสมัครได้ด้วย `REGISTRATION_OPEN=0` (admin เพิ่มคนเองด้วย CLI: `flask create-admin <user> <pass>` หรือ `flask approve <user>`)
- ผู้ใช้เปลี่ยนรหัสผ่านเองได้ที่ `/account`

## 4. Log

| ที่เก็บ | เนื้อหา |
|---|---|
| ตาราง `audit_logs` + หน้า **Log** (admin) | login สำเร็จ/ล้มเหลว/ถูกล็อก, สมัคร, อนุมัติ/ปฏิเสธ/ระงับ, ปักหมุด/ปลดหมุด/สลับลำดับ, เพิ่ม/แก้/ลบแหล่ง, กฎ, คำสำคัญ, คำขอจากนอก Tailnet ที่ถูกบล็อก — พร้อม ผู้ใช้ · IP จริง · ตัวตน Tailscale · User-Agent · เวลา |
| ตาราง `fetch_logs` + หน้า Log → การดึงข่าว | ทุกรอบการดึงของทุกแหล่ง: สถานะ, จำนวนใหม่/ที่เก็บ, เวลาที่ใช้, ข้อความผิดพลาด |
| `logs/audit.log` | สำเนา audit เป็นไฟล์ (หมุนไฟล์ 5 MB × 20) |
| `logs/access.log` | ทุก HTTP request: IP, method, path, status, user, ตัวตน Tailscale, UA |
| `logs/app.log` | log ระบบ/ตัวดึงข่าว/scheduler |

## 5. แหล่งข่าวและการดึง

หน้า **แหล่งข่าว** วางลิงก์ → กด **ตรวจสอบ** → ระบบเดาวิธีดึงและลองดึงตัวอย่างให้ก่อน → กด **เริ่มติดตามแหล่งนี้** (ดึงครั้งแรกทันที)

| วิธีดึง | ใช้กับ |
|---|---|
| `rss` | สำนักข่าวทั่วไป — ถ้า URL ที่ให้พัง ระบบ **ค้นหา RSS จากหน้าแรกเอง** (`<link rel=alternate>`, `/feed`, `/rss.xml` ฯลฯ) ไม่เจอค่อย **fallback เป็น Google News `site:โดเมน`** อัตโนมัติ |
| `gnews` / `gnews_query` | Google News RSS ตาม `site:โดเมน` หรือคำค้น (ใช้กับสื่อที่ไม่มี RSS และสื่อต่างประเทศแบบกรองเฉพาะข่าวที่เกี่ยวกับไทย) |
| `html` | อ่านหัวข้อจากหน้าเว็บโดยตรง (สำหรับเว็บที่ไม่มี RSS และ Google ไม่ index) |
| `telegram` | ช่องสาธารณะ `t.me/s/<ช่อง>` — ดึงโพสต์ได้ตรง |
| `youtube` | ฟีดของ channel (`channel_id` หรือ URL) |
| `bluesky` | โปรไฟล์ Bluesky (มี RSS ในตัว) |
| `rsshub` | เส้นทาง RSSHub / RSS-Bridge ที่คุณติดตั้งเอง (ตั้ง `RSSHUB_BASE`) — ใช้ดึงโพสต์ Facebook Page / X / TikTok / Instagram ได้ตรง |

**บัญชีบุคคลบน Facebook / X / TikTok / Instagram:** แพลตฟอร์มเหล่านี้ไม่มี RSS สาธารณะ ระบบจึงติดตาม "ข่าวที่กล่าวถึงบัญชี/ชื่อนั้น" ผ่าน Google News ให้โดยอัตโนมัติ ถ้าต้องการโพสต์ตรงให้ติดตั้ง [RSSHub](https://docs.rsshub.app) (Docker หนึ่งคำสั่ง) แล้วตั้ง `RSSHUB_BASE=http://127.0.0.1:1200` ปุ่ม "ตรวจสอบ" จะสร้างเส้นทางให้เอง

การคัดกรอง: ทุกข่าวผ่านตัวจัดหมวดด้วยคำสำคัญไทย/อังกฤษ (`jabta/classifier.py`) เก็บเฉพาะที่เข้า 5 หมวด (ปิดได้ด้วย `KEEP_ONLY_MATCHED=0` หรือติ๊ก "เก็บทุกโพสต์" รายแหล่ง) และจับกลุ่มข่าวเรื่องเดียวกันด้วย character-trigram similarity (`jabta/cluster.py`) จึงเห็นว่า "รายงานตรงกันกี่แหล่ง" และ "สื่อท้องถิ่น/บุคคลรายงานก่อนสื่อหลัก" หรือไม่

รายชื่อสื่อเริ่มต้น 148 แหล่ง (สื่อหลัก 42 · หน่วยงานรัฐ 14 · ท้องถิ่น 47 · ต่างประเทศ 45) อยู่ใน `jabta/seed_sources.py` — แก้แล้วรัน `flask seed` เพื่อเพิ่มรายการใหม่ (ของเดิมไม่ถูกทับ)

## 6. ปักหมุดและกฎอัตโนมัติ

- ปักได้สูงสุด 5 ข่าว อันดับ 1 ขึ้นเป็นข่าวใหญ่ · ลากสลับลำดับในหน้า **จัดข่าวเด่น** · ตั้งปลดหมุดอัตโนมัติ (ไม่มีข่าวใหม่ 12/24 ชม., พรุ่งนี้ 06:00, ไม่ปลด)
- กฎ: เงื่อนไข **หมวด + จำนวนแหล่งขั้นต่ำภายใน N ชม. + คำสำคัญ + ประเภทแหล่ง/กลุ่มบัญชี** → ปักหมุด / ปักอันดับ 1 / ติดระดับ (+ แจ้ง LINE) มีกฎเริ่มต้น 4 ข้อให้แก้ได้
- เมื่อหมุดเต็ม กฎจะเบียดเฉพาะหมุดที่มาจากกฎด้วยกัน ไม่แตะหมุดที่คนปักเอง

## 7. LINE (ไม่บังคับ)

ตั้ง `LINE_CHANNEL_ACCESS_TOKEN` (Messaging API ของ LINE OA) และ `LINE_TO` (userId หรือ groupId) ใน `.env` แล้วระบบจะ:
- ส่ง **สรุปเช้า** เวลา `MORNING_BRIEF_TIME` (06:30): ข่าวปักหมุด + สมควรรู้วันนี้ 4 ระดับ (`flask morning-brief` ทดสอบส่งทันที)
- ส่ง **แจ้งเตือนทันที** เมื่อแหล่งที่ตั้ง alert ไว้มีข่าวเข้าเงื่อนไข หรือกฎที่ติ๊ก "แจ้ง LINE" ทำงาน

## 8. คำสั่งที่มีให้

```bash
FLASK_APP=app.py flask seed [--reset]        # เพิ่มสื่อเริ่มต้น
FLASK_APP=app.py flask fetch [--source ID]   # ดึงข่าวทันที
FLASK_APP=app.py flask create-admin U P      # สร้าง/ตั้ง admin
FLASK_APP=app.py flask approve U             # อนุมัติผู้ใช้จาก CLI
FLASK_APP=app.py flask morning-brief         # ส่งสรุปเช้าเดี๋ยวนี้
```

## โครงสร้าง

```
app.py              จุดเริ่ม (Flask + scheduler)        config.py          ค่าตั้งค่าจาก .env
jabta/models.py     ตาราง (User, Source, Article, Story, Pin, Rule, Keyword, AuditLog, FetchLog)
jabta/auth.py       สมัคร/ล็อกอิน/รออนุมัติ/Tailscale auto-login      jabta/security.py  IP gate, audit()
jabta/fetcher.py    ตัวดึงทุกชนิด + auto-discovery + fallback         jabta/classifier.py จัดหมวด/ระดับ
jabta/cluster.py    จับกลุ่มข่าวเดียวกัน                             jabta/rules.py     กฎปักหมุด/ปลดหมุด/LINE
jabta/scheduler.py  งานเบื้องหลัง                                    jabta/seed_sources.py รายชื่อสื่อ
jabta/views.py      ทุกหน้าเว็บ                                      jabta/templates/, static/style.css
scripts/            install, run, tailscale-serve, systemd, launchd, docker
```

ฐานข้อมูลเป็น SQLite ที่ `data/jabta.sqlite3` (เปลี่ยนเป็น PostgreSQL ได้ด้วย `DATABASE_URL`) — สำรองข้อมูลแค่คัดลอกโฟลเดอร์ `data/` และ `logs/`
